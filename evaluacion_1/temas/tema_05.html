Tema 5 · Bloque C · Primera evaluación

Lenguajes, aplicaciones y utilidades

Elegir software exige distinguir la tarea, el tipo de herramienta, el formato de intercambio y las condiciones de uso; automatizar exige además expresar instrucciones sin ambigüedad.

  • 5 sesiones
  • 3 prácticas obligatorias
  • 1 evaluación Moodle
  • Trabajo en el aula

Al terminar podrás:

  • clasificar software por función y forma de ejecución;
  • elegir una herramienta con criterios verificables;
  • explicar cómo se traduce un lenguaje a instrucciones;
  • automatizar una tarea breve y documentar su prueba.

Pregunta guía
Si varias herramientas pueden abrir un archivo, ¿cómo decidimos cuál resuelve mejor la tarea y permite repetir el resultado?
01 / ECOSISTEMA

El software forma capas que cooperan

El firmware inicia y controla funciones cercanas al hardware; el sistema operativo administra recursos; las bibliotecas ofrecen componentes reutilizables; las aplicaciones resuelven tareas del usuario. Una herramienta puede apoyarse en todas las capas sin mostrarlas.

CapaResponsabilidadEjemplo
FirmwareInicio y control básicoUEFI de un equipo
SistemaProcesos, memoria, archivos y dispositivosGNU/Linux, macOS, Windows
BibliotecaFunciones reutilizablesLectura de imágenes o cifrado
AplicaciónTarea orientada al usuarioEditor, navegador, hoja de cálculo

La clasificación no siempre es rígida: un navegador es aplicación, pero también ejecuta aplicaciones web y ofrece servicios a extensiones.

02 / EXPRESIÓN

Cada lenguaje elige un nivel de abstracción

El lenguaje máquina codifica instrucciones para una arquitectura. El ensamblador usa nombres próximos a esas instrucciones. Los lenguajes de alto nivel permiten expresar datos, decisiones y repeticiones sin gestionar cada detalle del procesador.

Un lenguaje incluye sintaxis —formas válidas— y semántica —qué significan—. También incorpora tipos, estructuras y bibliotecas. Python favorece legibilidad y experimentación; C permite control cercano de memoria; SQL expresa consultas sobre datos. No existe un lenguaje mejor para todo.

Idea claveElegir lenguaje es elegir qué detalles controlar, cuáles delegar y qué ecosistema de herramientas utilizar.
03 / EJECUCIÓN

El código fuente necesita un traductor y un entorno

Un compilador analiza el programa y produce otro código antes de ejecutarlo. Un intérprete ejecuta instrucciones mediante otro programa. Muchos entornos combinan ambos enfoques: generan una representación intermedia y una máquina virtual la ejecuta o vuelve a compilar.

Error de sintaxis

La forma no cumple las reglas y el traductor no puede analizarla.

Error de lógica

El programa se ejecuta, pero el procedimiento no produce el resultado esperado.

Ejemplo de automatización legible

para cada archivo de la carpeta:
    si su extensión es ".jpg":
        moverlo a la carpeta "imagenes"

Este pseudocódigo expresa selección, condición y acción, pero aún necesita precisar colisiones de nombre, mayúsculas y qué ocurre si la carpeta no existe.

04 / TAREAS

Aplicación local, web y servicio no son equivalentes

Una aplicación local se instala y usa recursos del dispositivo. Una aplicación web se ejecuta entre navegador y servidores. Un servicio en la nube puede almacenar datos, colaborar y sincronizar. Las diferencias afectan conexión, privacidad, compatibilidad, actualización y posibilidad de exportar.

El formato de trabajo puede ser propietario o abierto. Para colaborar, no basta con que ambos vean el documento: deben conservar contenido, estructura, accesibilidad y capacidad de edición. Exportar una copia no siempre mantiene fórmulas, comentarios o capas.

CriterioPregunta verificable
Función¿Realiza la operación necesaria y con qué límites?
Interoperabilidad¿Importa y exporta un formato acordado sin pérdidas?
Privacidad¿Qué datos salen del equipo y quién los conserva?
Accesibilidad¿Puede usarse con teclado y tecnologías de apoyo?
Coste y licencia¿Qué usos, instalaciones y redistribución permite?
05 / MANTENIMIENTO

Las utilidades observan, transforman y protegen

Compresores, verificadores, gestores de paquetes, monitores, herramientas de copia y utilidades de red cumplen tareas acotadas. Algunas tienen interfaz gráfica y otras se usan desde terminal. Una orden escrita puede repetirse y auditarse, pero también causar cambios masivos: primero se prueba sobre una copia pequeña.

Un script encadena operaciones para automatizar. Debe declarar entradas, producir un registro, tratar errores previsibles y evitar sobrescribir sin confirmación. Automatizar un proceso mal definido solo permite equivocarse más deprisa.

Automatización segura

Previsualiza, limita el alcance, conserva una copia y verifica el resultado. Nunca ejecutes una orden copiada sin entender rutas, permisos y efectos.

06 / DECISIÓN

Una elección defendible compara evidencia, no popularidad

Primero se formula la tarea y se separan requisitos imprescindibles de preferencias. Después se prepara un archivo de prueba representativo, se ejecuta la misma operación en cada candidato y se registran resultados. La decisión debe poder revisarse si cambian requisitos o versiones.

  1. Definir producto final, usuarios y restricciones.
  2. Elegir criterios y una forma de medirlos.
  3. Probar el mismo caso en las alternativas.
  4. Registrar pérdidas, tiempo, errores y condiciones.
  5. Justificar la elección y reconocer sus límites.
07 / SALIDA

Lo esencial

  1. Firmware, sistema, bibliotecas y aplicaciones cumplen responsabilidades distintas.
  2. Los lenguajes abstraen detalles y se adaptan a problemas diferentes.
  3. Compilar e interpretar son estrategias de traducción y ejecución.
  4. Un formato compartido debe probarse, no suponerse.
  5. Una utilidad automatiza tareas acotadas y necesita límites seguros.
  6. Elegir software exige requisitos, pruebas y evidencia reproducible.
08 / EVIDENCIAS

Prácticas del tema

Las tres prácticas obligatorias se realizan de principio a fin en el aula y dejan un producto comprobable. No hay deberes.

La misma instrucción, tres niveles

T05-P01 · OBLIGATORIA

Expresa una operación sencilla como instrucción cotidiana precisa, pseudocódigo y pequeño programa ejecutable proporcionado en el aula; compara qué detalles aparecen en cada nivel.

Producto
apellido_nombre_t05_p01.zip con texto, código y registro de ejecución.
Tiempo
Una sesión individual con prueba por parejas.
Comprobación
Entrada y salida definidas, correspondencia entre versiones, tres casos de prueba, error corregido y captura o registro de resultados.

Ensayo de interoperabilidad

T05-P02 · OBLIGATORIA

Crea un documento de prueba con estructura, tabla, imagen y elemento accesible; intercámbialo entre dos aplicaciones o formatos y registra qué se conserva y qué se pierde.

Producto
apellido_nombre_t05_p02.pdf más archivos original y exportado.
Tiempo
Una sesión en parejas; informe individual.
Comprobación
Mismo caso de prueba, cinco criterios, evidencias antes/después, pérdidas descritas y recomendación condicionada al uso.

Utilidad segura para un lote

T05-P03 · OBLIGATORIA

Automatiza la clasificación o el renombrado de un lote de archivos de muestra. Ejecuta primero una previsualización, trata una colisión y verifica que no se pierden archivos.

Producto
apellido_nombre_t05_p03.zip con script, lote de prueba, instrucciones y bitácora.
Tiempo
Dos sesiones individuales con revisión de seguridad por parejas.
Comprobación
Alcance limitado, copia inicial, nombres con guion bajo, caso normal y caso límite, recuento antes/después y ejecución reproducible.
Prácticas voluntarias: solo se habilitan después de completar todas las obligatorias de la evaluación. Se aplican únicamente si mejoran la media de prácticas. Prácticas: 70%; sin notas mínimas.
