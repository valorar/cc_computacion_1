Pregunta guía
¿Qué evidencias permiten afirmar que un programa resuelve lo acordado y no solo que «parece funcionar»?
01 / PROBLEMA

Delimitar antes de construir

Un proyecto abordable identifica usuario, necesidad, entradas, salidas, restricciones y lo que queda fuera. «Gestionar datos» es amplio; «resumir mediciones del aula y señalar ausencias» es verificable.

DecisiónPregunta comprobable
Entrada¿Qué formato acepta y qué ocurre si falta?
Salida¿Qué archivo o mensaje produce?
Límite¿Qué no resuelve esta versión?
Éxito¿Qué prueba demuestra cada requisito?
02 / DISEÑO

Datos, funciones y flujo principal

El diseño traduce requisitos a responsabilidades. El flujo principal coordina; otras funciones validan, calculan y presentan.

def cargar_datos(origen):
    """Devuelve una colección o None si no puede cargarse."""
    # La implementación depende del formato acordado.
    return None

def main():
    datos = cargar_datos("datos.txt")
    if datos is None:
        print("No se pudieron cargar los datos.")
        return
    print("Datos listos:", len(datos))

if __name__ == "__main__":
    main()

El esqueleto es incompleto a propósito: define interfaces y error sin resolver ningún proyecto.

03 / ITERACIONES

Una versión ejecutable cada vez

Una iteración añade un comportamiento comprobable: entrada mínima, cálculo, validación y presentación.

  1. Plan: elegir un criterio pequeño.
  2. Construcción: modificar lo necesario.
  3. Comprobación: ejecutar y guardar resultados.
  4. Decisión: corregir, aceptar o replantear con motivo.
Evita la gran integración final

Integra pronto y en incrementos pequeños para no ocultar varias causas bajo un síntoma.

04 / CALIDAD

Pruebas ligadas a requisitos y riesgos

Cada criterio necesita al menos una prueba. Vacíos, duplicados, límites, caracteres inesperados y ausencia de resultado merecen casos propios.

casos = [
    {"nombre": "normal", "entrada": [2, 4], "esperado": 3},
    {"nombre": "vacio", "entrada": [], "esperado": None},
    {"nombre": "duplicado", "entrada": [4, 4], "esperado": 4},
]
for caso in casos:
    print(caso["nombre"], caso["entrada"], caso["esperado"])

La tabla no ejecuta la función del proyecto: prepara datos trazables para conectarlos a cada implementación.

05 / ENTREGA

Código, documentación y demostración

Una entrega reproducible incluye instrucciones, archivos, decisiones, límites y resultados. La demostración muestra un éxito y un límite.

  • Otra persona ejecuta el programa siguiendo el README.
  • Los archivos usan guion bajo y no rutas personales.
  • Las pruebas enlazan requisitos con salidas.
  • Fuentes y ayudas están reconocidas.
  • Los límites conocidos se explican.
06 / SALIDA

Lo esencial

  1. El proyecto comienza delimitado.
  2. El diseño separa responsabilidades y fallos.
  3. Cada iteración termina ejecutable.
  4. Las pruebas nacen de requisitos y riesgos.
  5. La entrega debe reproducirse y explicar límites.

Comprobación rápida: explica una idea con un ejemplo ejecutado y conserva la salida como evidencia.
