Tema 10 · Bloque D · Segunda evaluación

La web como documento público

Publicar en la web significa construir documentos semánticos, enlazados y adaptables que otras personas y máquinas deben poder interpretar.

  • 7–8 sesiones
  • 3 prácticas obligatorias
  • 1 evaluación Moodle
  • Trabajo en el aula

Al terminar podrás:

  • crear documentos HTML con estructura semántica y sintaxis válida;
  • separar contenido HTML de presentación CSS;
  • construir enlaces y rutas relativas portables;
  • comprobar accesibilidad, adaptación y publicación de un micrositio.

Pregunta guía
¿Qué necesita un sitio para seguir siendo comprensible, accesible y navegable fuera del ordenador donde se creó?
01 / TEORÍA

HTML describe la estructura

Un documento HTML declara idioma, metadatos y un cuerpo organizado. Elementos como header, nav, main, section y footer expresan función. Los encabezados forman una jerarquía y no se eligen por tamaño.

La etiqueta correcta aporta significado incluso sin CSS. Un párrafo no debe usarse como botón ni una lista construirse con guiones y saltos de línea.

02 / TEORÍA

CSS presenta sin borrar el significado

CSS selecciona elementos y aplica color, espacio, tipografía y disposición. La cascada resuelve reglas según origen, especificidad y orden. Clases reutilizables evitan estilos repetidos; los nombres describen función mejor que apariencia temporal.

El modelo de caja suma contenido, relleno y borde. Con box-sizing: border-box, el ancho declarado incluye relleno y borde, lo que facilita diseños predecibles.

03 / TEORÍA

Enlaces y rutas hacen un sitio

Una URL absoluta incluye protocolo y dominio; una ruta relativa se interpreta desde el archivo actual. ../ sube una carpeta. Cambiar un archivo de lugar altera sus rutas relativas, por eso la estructura de carpetas debe planificarse.

En un archivo temas/tema_10.html, ../../assets/css/estilos.css sube dos niveles y entra en assets/css.

04 / TEORÍA

Adaptación y accesibilidad desde el inicio

El diseño adaptable evita anchos fijos y permite que contenido y navegación funcionen con pantallas y zoom distintos. Imágenes fluidas, rejillas flexibles y consultas de medios ayudan, pero el contenido debe mantener orden lógico.

Accesibilidad básica: idioma, foco visible, enlace para saltar, controles con nombre, contraste, texto alternativo y navegación completa con teclado.

05 / TEORÍA

Validar y publicar es comprobar

El validador detecta etiquetas mal anidadas, atributos incorrectos e identificadores repetidos. Las herramientas del navegador muestran red, estilos y tamaños. Publicar exige probar desde la dirección pública: las rutas pueden funcionar localmente y fallar por mayúsculas o carpetas.

Nunca se publica información personal, credenciales, soluciones o contenido sin licencia. La web pública puede copiarse aunque luego se retire.

06 / SALIDA

Lo esencial en seis frases

  1. HTML expresa estructura y significado.
  2. CSS controla presentación mediante cascada y caja.
  3. Las rutas relativas dependen de la ubicación del documento.
  4. Un sitio debe funcionar con teclado, zoom y distintos anchos.
  5. Validar ayuda a descubrir errores antes de publicar.
  6. La publicación exige revisar privacidad, licencias y enlaces públicos.

Comprobación personal: explica cada frase con un ejemplo del tema y señala qué evidencia permitiría verificarlo.

07 / EVIDENCIAS

Prácticas del tema

Las tres prácticas son obligatorias y se realizan íntegramente durante las clases. Cada una deja una evidencia material revisable; la ayuda y la observación informal sirven para aprender, no aportan nota.

Documento semántico

P01 · OBLIGATORIA

Convierte un contenido plano en una página HTML con metadatos, jerarquía, navegación, tabla o figura y enlaces funcionales.

Producto
apellido_nombre_t10_p01.html.
Tiempo
Dos sesiones; trabajo individual en el aula.
Comprobación
HTML válido, idioma y título, un solo main, encabezados coherentes, recursos con alternativa y navegación por teclado.

Sistema visual adaptable

P02 · OBLIGATORIA

Crea una hoja CSS externa para la página anterior con variables, caja, estados de foco y una adaptación para pantalla estrecha.

Producto
apellido_nombre_t10_p02.zip con HTML, CSS y recursos locales.
Tiempo
Dos sesiones; trabajo individual con prueba cruzada en el aula.
Comprobación
Sin estilos en línea, selectores reutilizables, contraste, foco visible, sin desplazamiento horizontal a 320 px y lectura correcta al 200%.

Micrositio publicado y auditado

P03 · OBLIGATORIA

Construye tres páginas enlazadas, publícalas en el espacio indicado y realiza una auditoría de rutas, validación, accesibilidad y privacidad.

Producto
apellido_nombre_t10_p03.zip y informe_t10_p03.pdf con URL pública y evidencias.
Tiempo
Tres o cuatro sesiones; parejas, todo el ciclo en el aula.
Comprobación
Tres páginas navegables, rutas relativas portables, validación documentada, teclado y móvil comprobados, licencias registradas y ausencia de datos sensibles.
Prácticas voluntarias: solo se desbloquean después de completar todas las obligatorias de la evaluación. Si hay N obligatorias, se toman las N mejores calificaciones entre obligatorias y voluntarias terminadas. Una voluntaria incompleta o que no mejore la media se ignora; nunca reduce la nota ni permite superar 10.
08 / COMPRENDER

Evaluación Moodle del tema

Al finalizar el tema habrá un cuestionario autocorregible, calificado y registrado en Moodle. Mediante casos breves pedirá interpretar etiquetas semánticas, predecir rutas relativas, resolver cascada sencilla, detectar una barrera de accesibilidad y escoger una prueba de publicación. No se publica aquí el banco de preguntas ni sus soluciones.

  • Un cuestionario Moodle autocorregible por tema.
  • Forma parte del 30% correspondiente a evaluaciones Moodle; las prácticas forman el 70%.
  • Sin nota mínima, puerta de acceso ni compensación entre apartados.
  • Se completa en el aula y no sustituye ninguna práctica.
  • La retroalimentación se muestra una vez cerrado el intento según la configuración docente.
